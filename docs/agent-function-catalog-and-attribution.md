# Agent function catalog and attribution

Gonvex applications keep one executable API. The UI and an agent invoke the
same Query, Reducer, or Action. The generated catalog describes that API but
does not grant access.

## Declare an interactive function

```ts
export const start = reducer({
  interactive: true,
  description: "Start a task and assign the acting member.",
  agent: {
    tags: ["tasks", "workflow"],
    confirmation: "none",
  },
  args: schema.object({
    taskId: schema.id("tasks"),
    expectedVersion: schema.number({ integer: true }),
  }),
  result: schema.object({
    taskId: schema.id("tasks"),
    version: schema.number({ integer: true }),
  }),
  offline: { mode: "onlineOnly", reason: "requires current workflow state" },
  nonOptimisticReason: "workflow state is server-authoritative",
  run: async (ctx, args) => {
    // Apply the same permission checks used for UI calls.
  },
});
```

Public Queries and Reducers keep their interactive default during migration.
Public Actions enter the catalog only with `interactive: true`. `internal: true`
and `interactive: false` functions are excluded. Metadata must be a literal so
the CLI can extract and sign it without executing application code.

Confirmation values are `none`, `required`, and `destructive`. Gonvex records
the value in the catalog. The agent host decides how to obtain confirmation
before calling a function.

## Generate the catalog

```bash
gonvex functions emit --format ndjson --output agent-api.ndjson
gonvex functions emit --format typescript --output agent-api.d.ts
gonvex functions check
```

NDJSON stores one complete JSON object per line. Each object contains the
public path, kind, exact portable argument and result schemas, classification,
offline policy, optimistic transaction, description, sorted tags,
confirmation requirement, and module artifact hash. Output order and bytes are
deterministic across checkout directories.

The TypeScript form renders entity IDs as `Id<"table">`, optional fields as
optional properties, and `schema.any()` as `JsonValue`. It does not claim more
precision than the declaration provides.

## Invoke a catalog function

Only an Action declared with `profile: "agent"` and
`capabilities: { functions: true }` receives the invocation capability:

```ts
export const runAgent = action({
  profile: "agent",
  capabilities: { functions: true },
  args: agentRunArgs,
  result: agentRunResult,
  run: async (ctx, request) => {
    return ctx.functions.invoke({
      path: request.path,
      args: request.args,
      artifactHash: request.artifactHash,
    });
  },
});
```

The Rust host checks the active artifact hash, interactive classification,
portable argument schema, tenant route, current Member status, nesting depth,
and Action recursion before dispatch. It then invokes the same application
function used by the UI. A stale hash fails with code
`STALE_AGENT_CATALOG`. The caller should refresh the generated catalog and
retry only after reconsidering the new contract.

The capability never exposes SQL, database credentials, Control Plane access,
or client-selected actor identities.

## Trusted attribution

Every function context contains immutable `ctx.invocation` data generated by
the host. Direct browser calls use channel `ui`. Delegated calls use `agent`.
API-key, scheduler, and system work use their own channels.

The context records the authenticated Account, authoritative tenant Member,
root and current command IDs, parent command ID, artifact hash, and a
server-created agent execution ID. Delegated work sets
`onBehalfOfMemberId` to the acting Member. Client arguments cannot replace any
of these fields.

Reducer commits record sanitized provenance once in the same Postgres
transaction as the business rows. The change feed preserves
`originCommandId` for optimistic reconciliation and carries the sanitized
transaction provenance to the Local Replica. Rollback commits neither business
rows nor provenance.

Durable Action outbox entries and scheduled jobs retain the root provenance.
Their immediate channel changes to `system` or `scheduler`, while the root
initiator and acting Member remain attributable.

## Whagons cutover

1. Add literal metadata to each interactive application function.
2. Generate both catalog files during the TypeScript module build.
3. Give the agent ordinary grep and file-read access to those files.
4. Replace `assistantApprovedActions` with `ctx.functions.invoke` from one
   agent-profile Action.
5. On `STALE_AGENT_CATALOG`, reload the generated artifact catalog before the
   next tool call.
6. Keep authorization inside the existing Query, Reducer, and Action handlers.

Skills contain product and workflow knowledge. The generated Gonvex catalog
defines executable functions and schemas. Agents do not need to load a skill
before executing an operation. Skills are not authority for function names or
parameters.
