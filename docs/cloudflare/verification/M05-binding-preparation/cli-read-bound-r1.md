# CLI input-bound correction after the 24968803 review

The independent [pinned review](https://github.com/Whagons-International/gonvex/pull/421#pullrequestreview-5887072404) found that a pathname `stat` followed by unbounded `readFile` accepted an oversized FIFO and waited indefinitely on an idle FIFO. The original review and its failed reproductions remain unchanged.

The CLI now opens once with nonblocking read flags, validates that opened descriptor as a regular file, and reads at most the existing byte cap plus one overflow byte. It rejects an oversized actual read even if the file grew after metadata observation. Binding input keeps its 64 KiB cap; replay keeps its 8 MiB cap. Handles close in `finally`. Unsupported input and parse failures retain exit 1 and the fixed `monitor-input-integrity` message without printing input, paths or errors. Valid binding declarations still return BLOCKED/exit 2 and cannot enable execution. The estimate command is unchanged.

Local verification used the corrected source in an owned immutable-source build context: 135 monitoring tests (all previous 132 plus three new tests), 29 conformance tests, schema generation/freshness, dashboard/template codegen, shipped template catalogs and declarations, root/Control Wrangler types, docs metadata/Next typegen/TypeScript passed. No tracked generated output drift; complete-base runtime cycles remain 1→1 with no added cycle. New actual-CLI tests cover the UTF-8 byte boundary, a real regular file grown after its metadata observation through an owned fault-injection preload, and idle FIFOs without writers. They do not change the original assertions.

The first resource invocation omitted its required unit and ran no payload. Two subsequent generator setup attempts failed because this owned source context lacked module-SDK package resolution. Compiling the exact owned source and adding only owned project-resolution links fixed setup. No install or shared dependency/default-dist write occurred. The second attempt reused a dashboard log filename and overwrote the first full log; the original first result and captured thread output remain, but complete first-log retention is not claimed. The separate second failure and corrected third run are retained. Exact commands, source/tool/raw hashes, headroom and cgroup results are in [the correction receipt](cli-read-bound-r1.json).

This is a local input/resource-bound fix only. The public SDK evidence method remains an unimplemented proposal. Auth, scope, effects/cleanup, durable command cursor, authoritative read, separate applied client, hosted monitoring, original P1–P5 drills and all full M05/duration/activation gates remain UNMET. A NEW independent recheck of the corrected pin is required; old review or CI is not relabelled as that proof.
