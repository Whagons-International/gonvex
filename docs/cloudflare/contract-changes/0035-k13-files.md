# 0035: K13 files: IB1 against the Whagons call sites, private-file URL scope, upload paths

Date: 2026-11-11. Status: **proposed by K13; waiting for the lead.** Affects: K07, K12, K13, K19, K20, M01, V01,
`CONTRACT.md` D.1 "Storage and files" and E.d.

K13 implements IB1 (0001) with 0012 R12 and R13 as written: a private file is refused to anyone but its owner on every
URL mint, every signed download, every metadata read (Action and Reducer), every delete and the sandbox read, and
`ownerId` on create must name the caller unless the caller is a system principal. Checking that rule against the
Whagons sources (whagons5-client `3da74de090`, `gonvex/`) found two conflicts. §1 is decided in code, pending the lead's
confirmation. §2 needs a ruling: with IB1 as written, Whagons call recordings break.

## 1. Owners are Member ids in Whagons (implemented: account **or** Member id)

Six upload call sites pass the caller's **Member** id as owner, not its account id: `files.ts:52`, `chat.ts:916`,
`documents.ts:991`, `taskResources.ts:1781`, `voiceTaskDrafts.ts:213`, `bugReports.ts:103`
(`generateUploadUrl({ visibility: "tenant", ownerId: memberId })`). `documents.ts:1022` then reads `metadata.ownerId`
and refuses the document unless it equals `ctx.member.id`, and `storageAccess.ts` compares owners with Member ids.

Read literally, "ownerId must equal the calling account" would refuse all six uploads, and overriding the owner with
the account id would make `documents.ts:1022` refuse every document. **K13 reads "the caller" as the caller's account
id or its tenant Member id**, for both the create rule and the read check. A Member id is the caller within its
tenant, which is the only place the file exists. Any other owner on create gets
`ownerId must be the calling account or its tenant member`.

**Lead:** confirm, or rule otherwise.

## 2. Call recordings are private files owned by a label (breaks under IB1; ruling needed)

`calling.ts:696` (`archiveRecording`) creates the recording as
`generateUploadUrl({ visibility: 'private', ownerId: 'calling-recording:<callId>', … })`. Later, `recordingUrl`
(`calling.ts:666`) and `transcribeRecording` (`:718`) mint download URLs for it, and `archiveRecording` reads its
metadata (`:686`, `:703`) and deletes it (`:695`). The app does its own access check first
(`ctx.tools.control({ op: 'read' })`). `storageAccess.ts` also refuses members any file whose owner starts with
`calling-recording:`. Users call `archiveRecording` from `CallDetailSheet.tsx:117` and `recordingUrl` from
`useCallingData.ts:64`. Scheduled runs also start these Actions.

Under IB1 as written:

- a user-started `archiveRecording` fails at `generateUploadUrl` (the owner names neither the caller's account nor
  its Member);
- `recordingUrl`, `transcribeRecording` and the metadata reads fail with `file not found` for every caller, because
  no caller is `calling-recording:<id>`. As in Rust, a scheduler principal with no account stores `tenant` files, so
  only the user-started path creates private recordings.

In Rust today these recordings are readable by any Action that holds the file id. The label is never a principal.

Options:

| | Rule | Effect |
|---|---|---|
| a | Keep IB1 strict | Call recording playback and transcription break until the app changes (`visibility: 'tenant'` would do; the app already gates access). The brief allows no app edit before cutover, so this is a regression at cutover. |
| b | **Label owners** (K13's recommendation): an owner that is neither an account id nor a Member id of the tenant (one indexed lookup in `members`) is a label, not a principal. A private file with a label owner may be created by any caller and minted or read by any caller in the tenant, as in Rust. IB1 holds in full for every file owned by a real account or Member. | Whagons works unchanged. The weaker rule applies only to files a module chose to give no principal owner. |
| c | Exempt Actions on a system or agent channel | Fixes the scheduled path only. `recordingUrl` is user-started, so playback still breaks. |

K13 ships (a), the rule as written, so nothing is weaker than ruled. If the lead picks (b), it is a small change in
`kernel/files/access.ts` (`mayAccess`, `ownerFor`) plus a `members` lookup.

## 3. Private-file download URLs carry their owner (implemented; R13)

R13 asks the proxy to refuse "a private file whose URL was not minted for its owner". A signed URL carries no caller,
and browsers fetch it without credentials. So **a private file's URL is signed with the owner bound in**:
`hex(HMAC-SHA256("gonvex-storage-private:" + secret, "{key}\n{exp}\n{ownerId}"))`. The proxy reads the row and verifies
the scope the row calls for. Only the owner-checked mints (`getUrl`, `generateDownloadUrl`) produce this scope.

- The URL shape is unchanged. Download signatures for `tenant` and `public` files and every upload signature stay
  byte-identical to Rust's (E.d.3 "keep").
- A Rust-minted URL for a private file stops working on the kernel at cutover. Download URLs last 10 minutes.
- **K19:** `/dev/storage/files` mints a URL for every row (D.1). Under IB1 the operator is not the owner, so the listing
  must not mint a private-scope URL. A plain URL for a private file gets 403 at the proxy. K13 proposes `url: null`
  for private rows. K13 does not build the listing: K19 owns `/dev`.

## 4. Upload paths and sizes (implemented; platform-forced)

| Case | Kernel | Rust |
|---|---|---|
| declared `size` ≤ 100 MB (`GONVEX_STORAGE_PROXY_MAX_BYTES`), or none | proxy `POST` URL, ticketed, single use | proxy URL when `GONVEX_PUBLIC_URL` is set |
| 100 MB < declared `size` ≤ 128 MiB | **direct presigned R2 `PUT`**, `If-None-Match: *` and `Content-Length` signed in; `headers` returns `If-None-Match: *` | same proxy URL |
| declared `size` > 128 MiB | `upload too large` | same |
| proxy body > 128 MiB by `Content-Length` | 413 `upload too large` | same |
| proxy body with no `Content-Length` | buffered, 413 above 32 MiB | buffered up to 128 MiB |

- The Worker request-body limit (100 MB on Free and Pro, S4) makes the 100 MB – 128 MiB band fail through any proxy.
  The direct URL is the S4 design (0016 G0-8).
- Single use for a direct upload comes from R2's conditional write, not a ticket. The worker never sees the PUT. The
  row stays `pending` until a read finalizes it, as in Rust's presign mode.
- **Whagons:** the web uploader (`src/lib/assetHelpers.ts`) uses only the URL. It always POSTs, never sends `size` and
  ignores `method` and `headers`. So web uploads always get the proxy URL, and a web upload over 100 MB fails at the
  platform with 413. Server-side callers that honour `method` and `headers` (`calling.ts`,
  `taskVideoProcessing.ts`) can use the direct path if they declare the size. A client change to declare sizes is a
  stage-3 item.

## 5. R26 count

**0 Whagons call sites use `ctx.storage.store`** (`grep` over `gonvex/` and `src/`). The kernel caps `store` at
32 MiB decoded with `storage content exceeds the 33554432 byte limit`. Rust's message format is kept with the new number.
The bytes are decoded and written in the Action Worker (`ActionFiles`), because 32 MiB of content is 43 MiB of base64,
more than one RPC argument can carry (0022 §4.4).

## 6. Smaller decisions (implemented)

- `_gonvex_files` and the ticket table `_gonvex_storage_uploads` (R6: Rust's columns minus the tenant) are created once
  per object instance by `TenantFiles.ensureSchema()` in the tenant object's constructor. Rust ran the DDL on every
  storage call. K03's capture skips `_gonvex%` tables, so neither is captured. K02 may move the DDL into its prelude.
- A proxy upload key with no ticket is refused (409). Rust accepted a "ticketless" claim for presign-era keys. The
  kernel mints no unticketed proxy URL (E.d.3 "always ticketed").
- The router finds the tenant object from the key's tenant segment (`idFromName(tenantId)`). Tenant ids are
  `random_id("tenant")`, which `safe_segment` leaves unchanged. An id it would change cannot be routed and fails closed
  with 404.
- Finalize: the R2 `head` runs before the update. In a Reducer it is awaited inside the Reducer's storage transaction,
  as Rust does inside its tenant transaction. Verified in local workerd; see follow-ups.
- Proxy URL TTLs are clamped to 1 s – 7 days (E.d.3 "adapt: clamp like presign").
