# 0016: Rulings at gate G0 (spike results)

Date: 2026-11-11. Status: decided (lead). Gabriel may override any row at G0 sign-off.
Inputs: `docs/cloudflare/spikes/S1-schema.md`, `S2-execution.md`, `S3-sockets.md`, `S4-long-actions.md`.

| # | Open item | Ruling |
|---|---|---|
| G0-1 | **0004** socket routing (tenant only in the `auth` frame) | **Gateway objects (option 2).** The upgrade goes to a gateway object chosen without the tenant (a shard of the connection id). The gateway holds the socket with the hibernation API, parses `auth`, and talks to the tenant object by RPC. S3: gateways of about 125 sockets hold 30 writes/s for 1,000 users, while one object tops out at about 10 fan-outs/s. Tenant-to-gateway RPC is 6–17 ms p50 in the same colo. Delivery keeps one interface with two placements; X01 triggers on frames per second. Gateway-to-tenant RPC must stay backward compatible for one version (deploy skew of 10–40 s, S3/S4). |
| G0-2 | **0005** loading bundles without `eval` | **Stage 1: the bundle is part of the deployed Worker version.** The Query/Reducer bundle is a 1,019 KiB gzip upload, inside the 10 MB limit, and starts in 261 ms (S2). K19's `/dev/sync` uploads a new Worker version through the Workers API. Hibernated objects adopt it on wake with no socket dropped. Active objects drop sockets (1006) and clients are back in 4–6 s (S3). The SDK then re-authenticates and picks up the new `artifactHash`, which is the observable effect of `system.reload`. **Spike S5** tests the Worker Loader before K19, to keep in-place `system.reload` without dropping sockets. |
| G0-3 | **0006** module savepoints | **Decided** as S2 proved it: one `ctx.storage.transaction(async)` per invocation. `SAVEPOINT`, `ROLLBACK TO` and `RELEASE` map to nested storage transactions held on a LIFO stack. Rust's "aborted until `ROLLBACK TO`" and "no commit after a caught SQL error" rules are kept. |
| G0-4 | **0010** change capture | **Decided:** plain-SQL capture triggers, generated by the A01 transform (T5). S1 showed correct change rows on the platform. |
| G0-5 | Deferred foreign keys (S2) | **Mandatory in K01/K04:** a deferred-FK violation at commit resets the whole object. Before leaving the invocation's transaction, the kernel checks only the rows written (from K03 capture) and fails the call with Rust's error class. Never rely on the commit to catch it. |
| G0-6 | **0017** liveness (S3) | **No SDK change in stage 1:** the SDK must work unchanged and nothing goes to the app. The kernel answers `{"type":"ping"}` by auto-response anyway (harmless and free). For dead-peer detection, a socket with no outbound frame for 20 s gets Rust's timer-driven `replica.watermark` at the current revision, so the edge's TCP stack can notice a dead peer. K14 measures the detection time on the platform and either meets the 10 s grace after detection or reports the gap. The SDK ping (`capabilities.ping`) is a stage-3 capability-flagged change. 0012 R22 is closed by this row. |
| G0-7 | **0018** platform WebSocket caps | **Accepted as proposed.** Conformance asserts that ≤ 32 MiB − 1 KiB is accepted and > 32 MiB refused. The kernel never sends a frame ≥ 32 MiB − 1 KiB; it splits or fails with a clear error. Amends 0012 R21. |
| G0-8 | Actions (S4) | Long Actions run as **Workflow steps**. Short Actions run in the Action Worker. **Queues are not used for Actions** (15-minute consumer limit, head-of-line blocking). Leases are persisted at claim and at half-life (about 24 rows per running hour). The Action Worker raises `limits.cpu_ms` for streaming (40–100 ms CPU per MB). Uploads over 100 MB use direct presigned upload (K13). |
| G0-9 | Hibernation (S3) | Every object uses alarms only, never timers, so idle tenants deploy without dropping sockets. Per-socket state lives in attachments of ≤ 16 KiB; the contract's 2 KiB assumption is lifted. |
| G0-10 | Provisioning (S1) | K02 provisions a new object by applying the release's **transformed** migrations in chunks (T7), or from a transformed schema image built once per release. Both must give the identical `sqlite_schema` and the same migration ledger as Rust. |
| G0-11 | 0012 R25, a runaway Reducer | **Still open.** K04 measures what an exceeded CPU limit does to the object's sockets and in-flight work, and proposes a per-call CPU guard. |
| G0-12 | Catalog cost (S2) | 95–99 % of rows read per Reducer are host catalog lookups. K04 caches catalogs per schema generation. `pragma_table_list` over the full schema costs about 14 s CPU (P03), so the kernel reads `sqlite_schema` instead. |
