# 0012: Lead rulings on the open items found during the contract freeze

Date: 2026-11-10. Status: decided (lead). Each ruling keeps Rust's observable behavior unless it says
otherwise. Items marked **V06** go to the security review with the ruling as the starting point.

| # | Item (CONTRACT.md) | Ruling |
|---|---|---|
| R1 | `/dev/sync` rollout stops at the first failed tenant; `docs/migrations.md` says it continues (D.2) | **Keep fail-fast.** Code is the reference. The docs are wrong; fixing them is outside this branch. |
| R2 | `/dev/sync` response does not list applied migrations (D.2) | **Keep** the Rust response shape. |
| R3 | Unknown-project fallback through `GONVEX_DEV_SYNC_KEY` (D.2) | **Keep.** K19 implements it with the key held as a Worker secret. |
| R4 | The CLI needs a synchronous `/dev/sync` response, but tenant rollout goes through a Queue (D.2.4) | **Adapt without a contract change:** the control object holds the `/dev/sync` request open until every tenant has applied the release or a deadline passes (default 10 min), then answers exactly as Rust does. No pollable status endpoint in stage 1. |
| R5 | A failed `/dev/sync` after migrations leaves new schema with old or new code and nothing undone; no lock against concurrent syncs (D.2) | **Keep the ordering** (migrate, install, activate). **Add** a per-project sync lock in the control object; a second concurrent sync gets HTTP 409. The lock is invisible to a single developer and closes a race Rust has; recorded here as an accepted deviation. |
| R6 | Control-plane tables that hold per-tenant work: `gonvex_scheduled_jobs`, `gonvex_storage_uploads` (E, table list) | **Move to the tenant object.** The tenant alarm drives the jobs; upload tokens are checked where the file row lives. Their columns and semantics are unchanged; the `tenant` column becomes implicit. |
| R7 | `gonvex_support_sessions`, `gonvex_support_commands`, `gonvex_control_idempotency` | **Control object.** Writes to support sessions happen only on change (Rust already answers repeats from memory). |
| R8 | `control.support.sendCommand` never pushes `support.command` because the broadcast only runs on the Query path (C.1 row 52) | **Keep** (no push). Code is the reference. A push is a stage-3 capability-flagged change. |
| R9 | Login and other Control Actions store full results, including plaintext tokens, in `gonvex_control_idempotency`, and a replay returns them before credentials are checked (C.3.9) | **Keep for parity in stage 1; V06.** The idempotency key is client-chosen random, so a replay needs that secret. The kernel adds expiry of these rows after 24 h (they are never pruned today); a replay after expiry runs the call normally, which re-checks credentials. |
| R10 | No rate limit on Control auth Actions on the member transport (C.5) | **Keep none in stage 1; V06** decides on the Rate Limiting binding. |
| R11 | Rust's process-local limiters (public functions, pending sockets, per-IP) (C.5) | **Adapt:** per-object counters in the object that owns the socket. A deployment-wide budget is not contract today and stays out. |
| R12 | `getMetadata` on a private file (E.d.4) | **Owner check**, as for downloads and delete (IB1). |
| R13 | `GET /storage/{key}` proxy re-checks nothing after signing (E.d.4) | **Replace (IB1):** the proxy looks up the file row and refuses a deleted file or a private file whose URL was not minted for its owner. |
| R14 | Impersonated and service-delegated sockets may run tenant-admin calls as the target, including `tenants.delete` (C, surprise 4) | **Keep for parity; V06.** |
| R15 | `control.tenants.mine`, default tenant choice at sign-in, and `support.listTenants` read every tenant database (C.4) | **Adapt:** the control object answers from its membership projection (`account_tenant_index`) and fans out to tenant objects only for the re-admission check, batched, at most 32 concurrent RPCs. K06 reports the fan-out cost per sign-in. |
| R16 | A login socket stays unauthenticated and closes at the 10 s auth deadline (C, surprise 5) | **Keep** (10 s is contract). |
| R17 | Strict frame decoding: any frame serde rejects closes with 1003 (A.1.9) | **Keep.** K05's handshake scenarios include an unknown `type` and a non-integer `device.viewportWidth`. |
| R18 | Rust sends `replica.reset` reasons `change-feed-lagged` and `change-feed-reset`, which the TS union lacks (A.6) | **Keep** the strings Rust sends. The TS union is documentation; the SDK treats unknown reasons as a reset. |
| R19 | TS messages Rust never sends (`query.patch`, `query.pagePatch`, `query.objectPatch`, `query.batch`, `query.fanout`, `replica.readyMany`) although the SDK advertises them (A.6) | **Defer.** The kernel sends what Rust sends. Using them is a stage-3 change. |
| R20 | Server advertises `replicaNativeRows`, `replicaSetDigest` and `replicaFieldPatches` to every socket, though the SDK never uses native rows and never reaches row patches while `replicaBatchFrames` is on (A.0, A.1.3) | **Replace:** the kernel advertises only capabilities it implements, so these three are absent from its `session.ready`. The P02 frame normalizer drops these three keys from Rust's `session.ready` before comparing. A client that never negotiates them sees no difference. |
| R21 | Members' sockets accept 64 MiB messages in Rust; Workers receive at most 32 MiB (A.1.7) | **Adapt:** the kernel's limit is 32 MiB. A larger frame fails at the platform. Conformance asserts the 32 MiB boundary, not 64. Reported to Gabriel as a platform-forced deviation. |
| R22 | Liveness through server pings (close 4000 `presence liveness timeout`) and the 30 s send stall, which drops the socket with a TCP reset and no close frame (A.1.8, E.e.4) | **Open until S3.** S3 reports the replacement; K14's grace time is set from it. |
| R23 | `ctx.now` stamped by the host, `runAfter` using the server clock, `Math.random()` throwing in server Queries (B.4) | **Keep** every one of these exactly. The determinism contract is what Rust does, not what would be cleaner. |
| R24 | `fetch` decodes response bodies as lossy UTF-8 (B, `action_calls.rs:488`) | **Keep** for parity; a binary-safe body is a stage-3 capability-flagged change. |
| R25 | A runaway Reducer cannot be stopped per call inside a tenant object; hitting the CPU limit resets the object (B.6) | **Open; S2 reports.** S2 measures what an exceeded CPU limit does to the object's other sockets and in-flight work. |
| R26 | `ctx.storage.store` accepts up to 128 MiB as base64 inside JSON (`rust/crates/runtime/src/storage.rs:271-319`); about 171 MiB of base64 cannot fit a 128 MB isolate (B.2a) | **Replace (platform-forced):** the kernel caps `store` at 32 MiB decoded and fails larger calls with a clear error naming the limit; larger files use `generateUploadUrl`. K13 reports how many Whagons call sites store more than 32 MiB. Reported to Gabriel with R21. |
