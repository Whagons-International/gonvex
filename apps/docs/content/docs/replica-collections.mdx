---
title: Replica Collections and Local Replica
description: Bounded persistent collections, atomic transactions, and offline completeness.
---

A Replica Collection keeps a bounded, authorized entity set in the Gonvex
Local Replica.

```ts
import { replicaCollection, visibility } from "@gonvex/module-sdk";

export const taskVisibility = visibility({
  table: "tasks",
  key: "id",
  sets: {
    workspaces: {
      table: "workspaceMembers",
      select: "workspaceId",
      joins: [],
      where: [{ table: "workspaceMembers", column: "memberId", context: "member.id" }],
    },
  },
  where: { operator: "inSet", column: "workspaceId", set: "workspaces" },
});

export const recent = replicaCollection({
  replica: {
    table: "tasks",
    key: "id",
    columns: ["id", "workspaceId", "title", "status", "updatedAt"],
    orderBy: "updatedAt",
    orderDirection: "desc",
    mode: "progressive",
    maxRows: 10_000,
    maxBytes: 50 * 1024 * 1024,
  },
});
```

The Local Replica stores normalized authoritative entities, optimistic
overlays, Live Query ID memberships, pending commands, and the applied server
revision. A `replica.transaction` updates all affected entities and memberships
before subscribers are notified once.

Web persistence uses IndexedDB. Expo/mobile uses `@gonvex/expo-sqlite`, which
updates normalized entity/query tables and the cursor in one SQLite
transaction.

Collections explicitly report `complete` or `partial`. Offline filters over a
partial collection are labeled as cached partial results.

The visibility plan is mandatory on the next module update. Gonvex compiles it
into snapshot and Live Query SQL, caches its revisioned context, derives its
dependency tables, and evaluates committed old/new rows before sending INSERT,
PATCH, or visibility DELETE changes. Equivalent resolved contexts share one
Live Query group; fingerprints are an optimization and never an authority.

Snapshot-cache followers release the socket's read fence while waiting for a
shared builder, before they own a SQL read clock. They reacquire it before
reading. Existing subscriptions can therefore receive commits and watermarks
while other collection opens wait. The cold-open quota is unchanged;
`/dev/metrics` exposes its limit, active count, peak and refusals under
`memory.snapshotCache` for load-test diagnosis.

Grant-source updates use the compiled alias, join and filter dependencies to
skip unrelated changed columns. Inserts, deletes, relevant updates and updates
without column evidence remain conservative. This avoids broad reconciliation
for an unrelated edit without weakening permission-change delivery.
