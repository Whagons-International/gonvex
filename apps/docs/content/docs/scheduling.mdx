# Scheduling and Background Jobs

Recurring jobs are declared in TypeScript module code. They target a Reducer or
Action and are extracted into the language-neutral module artifact.

```ts
import { action, cron, reducer, schema, tenantCron } from "@gonvex/module-sdk";

export const refresh = action({
  args: schema.object({}),
  result: schema.object({ refreshed: schema.boolean() }),
  run: async ({ fetch }) => {
    await fetch("https://example.test/refresh");
    return { refreshed: true };
  },
});

export const refreshEveryFiveMinutes = cron({
  name: "refresh-every-five-minutes",
  function: "refresh",
  intervalMs: 5 * 60 * 1000,
});

export const tenantCleanup = tenantCron({
  name: "tenant-cleanup",
  function: "tasks.cleanup",
  expression: "0 1 * * *",
});
```

The target function must be a Reducer or Action, never a Query. A tenant cron
runs once for each tenant with that tenant's verified context.

## One-shot work

Reducers and Actions can use the scheduler supplied in their context for
durable one-shot work. Work scheduled from a Reducer becomes visible only after
the Reducer commits. A rollback does not expose its scheduled job.

External work belongs in an Action. If the Action needs durable state, call a
Reducer. Database changes made by a Reducer are committed atomically and routed
from the committed change feed; there is no write declaration or manual
invalidation API.

## Durability

Recurring and one-shot jobs are persisted in the tenant's SQLite database and claimed with
renewable leases. They survive runtime restarts. Normal failures are recorded
in runtime metrics; retention, public cancellation, manual retry, and
dead-letter APIs remain limited beta features.
