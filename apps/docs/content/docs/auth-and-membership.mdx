# Auth and Membership

Gonvex separates global identity from tenant-local authorization:

```txt
Account
  Global authenticated identity.

Member
  Account's identity inside one tenant, including status, roles, teams,
  permissions, and tenant-specific profile fields.
```

One Account can have many Members. Application assignments should store the
tenant-local Member ID, not a global login ID.

## Project authentication modules

Each project selects one authentication mode:

```txt
gonvex-native
firebase
external-oidc
hybrid
```

The provider module does one job. It verifies a credential and returns the
provider, issuer, subject, and verified profile claims. Shared Gonvex host code
then resolves the Account, issues the Gonvex session, routes the tenant, and
checks the tenant's active Member row. Provider code cannot grant membership or
select a database.

Gonvex-native auth remains built in. Projects that already use Firebase can
disable it and use Firebase as the only provider:

```bash
npx gonvex auth configure firebase \
  --firebase-project-id my-firebase-project \
  --mode firebase \
  --signup-mode inviteOnly
```

The browser supplies a Firebase ID token through
`createFirebaseAuthAdapter`. Gonvex does not bundle Firebase, store the
Firebase password, or ask the user to sign in a second time. The same provider
contract supports generic external OIDC and future trusted-host adapters.

## Gonvex-native Google authentication

Enable the installation's central Google OAuth broker for a project:

```bash
npx gonvex auth add google --origin http://localhost:5173
npx gonvex auth status
npx gonvex auth doctor
```

Projects using Gonvex-native Google login do not need Firebase or a per-app
Google Cloud project. The runtime validates the account session before routing
it to a tenant.

## Tenant membership

```bash
npx gonvex auth tenants create "Acme" --owner owner@acme.example
npx gonvex auth tenants list
npx gonvex auth memberships add \
  --tenant <tenant-id> --email teammate@acme.example --role member
npx gonvex auth memberships remove --tenant <tenant-id> --email teammate@acme.example
```

The Control Plane's tenant index answers which tenants to show and where to
route. It is a projection, not the security authority. On every tenant
connection Gonvex checks the active tenant database for an active Member. A
revoked Member is denied even if a directory projection is stale.

## Frontend tenant switching

The client session carries the selected tenant. The frontend may choose a
tenant ID, but it cannot grant access:

```ts
client.setAuth({ token, tenant: nextTenantId });
```

When the tenant changes, the Local Replica uses a new scope. Data from the
previous tenant is not reused in the new scope, and visibility is revalidated
before the UI reports the connection as current.

## Module context

TypeScript modules receive the resolved identity as `ctx.auth.account`,
`ctx.tenant`, and `ctx.member`. Visibility plans use the same context keys:

```ts
import { visibility } from "@gonvex/module-sdk";

export const taskVisibility = visibility({
  table: "tasks",
  key: "id",
  sets: {},
  where: { operator: "eqContext", column: "assigneeId", context: "member.id" },
});
```

The server applies visibility to initial snapshots, Live Query windows, and
committed row changes. A row becoming invisible produces a client-local delete;
the database row itself is not deleted.

Use an explicit literal wrapper when access depends on stored state:

```ts
where: {
  operator: "eq",
  column: "visibility",
  value: { literal: "public" },
}
```

Set constraints accept the same `value: { literal: ... }` form on a joined
table. This lets a child row inherit access from a public parent while keeping
the rule in one visibility plan.

## Terminology

- `Account`: global identity and authentication profile.
- `Member`: tenant-local identity and authorization subject.
- `Tenant`: isolated customer, workspace, or account boundary.
- `Control Plane`: runtime-owned identity, directory, and routing database.
- `visibility`: centralized server-side row access plan.
