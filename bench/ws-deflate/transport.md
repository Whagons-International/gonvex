# Transport compatibility

The plain connection path still uses axum's `WebSocketUpgrade` and tokio-tungstenite. Only a connection with an accepted RFC 7692 offer uses ratchet_core/ratchet_ext. Axum's tungstenite adapter does not expose a permessage-deflate codec or extension hooks. Ratchet provides frame extension hooks, so the browser can inflate text natively while the runtime continues to exchange the same JSON. It is retained after removal of ws-pmd.

The in-crate parser follows [RFC 6455 section 9.1](https://www.rfc-editor.org/rfc/rfc6455#section-9.1) and [RFC 7692 section 7.1](https://www.rfc-editor.org/rfc/rfc7692#section-7.1). It reads every header line and offer, parses quoted token values, validates all four PMD parameters, and declines unknown parameters, duplicates and invalid values. A later valid offer can win. Malformed extension syntax returns HTTP 400 even after an earlier valid offer. Disabled compression skips this parser. Offers with no usable agreement use the legacy transport. Both no-context-takeover parameters are included in every agreement. Server windows are 9 through 12 bits; a server window offer of 8 is declined because flate2 cannot honor it. Client windows are 8 through 15 bits; the 8-bit case uses a 9-bit inflater, which can decode an 8-bit dictionary. `client_max_window_bits` is returned only when offered. No SDK or JSON protocol change is required.

The inflater allocates at FIN only, uses fixed scratch space with a limit-plus-one overrun detector, restores the RFC sync-flush trailer, and checks its boundary with a synthetic empty final block. BFINAL streams within a message start fresh raw inflate state and continue rather than truncating the message. It releases every codec before returning. Outgoing compression remains flate2/zlib-rs level 1, with a 1 KiB threshold and a plain-frame fallback if output grows.

## Behaviors and evidence

| Behavior | Preserved behavior and possible difference |
| --- | --- |
| Ping/pong | Both reply with the same pong payload and tolerate unsolicited pongs during fragmentation. Control frames never receive RSV1, including at thresholds 1 and 125. Ratchet flushes its automatic pong before yielding Ping; tungstenite queues its response for the next flush/read/write. The runtime ignores Ping/Pong on both paths. |
| Application close | Wire tests preserve codes 1000, 1001, 1008, 1009, 1011, 1012, 1013, 3001, 4001 and 4999, including reasons. Ratchet's enum cannot represent 1014; the adapter maps unsupported outbound codes to 1002. `Close(None)` becomes 1000 on the negotiated path rather than an empty close payload. The runtime currently sends explicit supported close codes. |
| Peer close | Ratchet acknowledges the code immediately, omitting the peer's reason. Tungstenite queues a reply including the reason; the runtime drops on receipt of Close, so that queued reply need not reach the wire. A paired test records immediate-drop legacy EOF versus Ratchet's code-only acknowledgement. Both expose the received reason to the application. |
| Frame/message limits | Both paths receive the same configured limits. The runtime uses its public payload cap on public connections and 64 MiB messages/16 MiB frames otherwise. A frame guard checks length before Ratchet allocates payload. Both reject a 4,097-byte frame and a fragmented 4,097-byte message with 4,096-byte test limits, while accepting exactly 4,096 bytes. Inflation additionally enforces the expanded size. Ratchet also bounds accumulated compressed wire bytes, so a deliberately inefficient compressed encoding exceeding the cap can be rejected even when its decoded content fits. |
| Error shutdown | Both paths reject oversized and invalid UTF-8 text without delivering the message. In the immediate-drop test callback, tungstenite yields an error and drops without a close frame. Ratchet emits 1002 for frame/message overflow and inflater errors; the adapter emits 1007 for invalid decompressed text. This is acceptance parity, with a documented wire close difference. |
| Fragmentation | Both reassemble text and binary messages, including a UTF-8 code point split across frames. Compressed fragments inflate once at FIN. Ping/Pong interleaving preserves accumulated data; RSV1 on continuation/control frames is rejected. Repeated cancelled application receives cannot cancel Ratchet's owned reader. Outgoing runtime sends are complete messages on both paths. |
| UTF-8 | Both validate reassembled text; compressed text is validated after inflation. Plain and compressed invalid text tests reject bytes 0xff. Close-reason UTF-8 validation remains in the underlying transports. |
| Backpressure | Every application send awaits transport writing/flushing. Ratchet's owned reader uses a channel of capacity one, so it can hold one queued message and one in-flight read/delivery, rather than an unbounded application queue. Control replies share Ratchet's write lock. An ordered 128-message burst test with delayed consumption proves no drops or reordering on either path; it does not measure kernel-buffer limits or prove all scheduling interleavings. |

`cargo test -p gonvex-websocket --lib tests::` covers this table, codec round trips, independent messages, malformed headers and generated adversarial inputs. These are focused tests, not an Autobahn certification or a complete equivalence proof. The optional transport can be disabled with `GONVEX_WS_COMPRESSION=false`.
