# v0.5.2-sqlite.0

SQLite storage prerelease, published on npm's `sqlite` dist-tag (the `staging` and
`latest` tags are unchanged). Built from the SQLite lab branch at `3524878c`
(`staging` `b50ded9` + the SQLite storage commits) merged with the finished
performance branches (#285):

| Branch | Commit | What |
|---|---|---|
| `perf/profiler` | `a7bfff3e` | always-on stage histograms, stall detector, `/dev/profile` |
| `perf/sqlite-writer` | `9ca97588` | checkpoints off the writer, process-wide SQLite cache budget |
| `perf/native-reducers` | `d5375d3c` | V8 isolates in the runtime process (`GONVEX_MODULE_HOST_IN_PROCESS=false` falls back) |
| `perf/v8-memory` | `7c3cfcd6` | malloc_trim, one-byte source, split Query/Reducer bundle (`module.split`) |
| `perf/presence` | `8a156eb1` | presence v2 in runtime memory, SIGTERM graceful stop, support last-seen refresh |
| `perf/ws-buffers` | `b6f9d16e` | smaller per-connection WebSocket buffers and futures |

- Every tenant and the Control Plane are SQLite files under `GONVEX_DATA_DIR`;
  see `docs/sqlite-storage.md`. `gonvex-admin export-sqlite` moves an existing
  Postgres deployment.
- The runtime refuses to start while `DATABASE_URL` or
  `GONVEX_CONTROL_PLANE_DATABASE_URL` is set. One runtime owns a data directory
  (`.gonvex.lock`); deploys must stop the old container first.
- Presence v2 (`GONVEX_PRESENCE_V2`) keeps presence in memory: after a runtime
  restart everyone shows offline until their client reconnects. Older clients
  stay visible through `GONVEX_PRESENCE_LEGACY_BEAT_PATHS` /
  `GONVEX_PRESENCE_LEGACY_TRANSITION_PATHS`. Contract: `docs/performance/presence-v2.md`.
- Apps regenerate their Gonvex artifacts with this CLI and ship SQLite tenant
  migrations. `"module": {"split": true}` opts into the split bundle.

Install with `pnpm add @gonvex/client@sqlite` (or pin `0.5.2-sqlite.0`).
