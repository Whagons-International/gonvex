# Gonvex 0.5.0

This release moves the supported server runtime to Rust and adds a generated
agent function catalog. TypeScript modules still declare only Query, Reducer,
and Action functions.

## Runtime

- The Rust runtime owns HTTP and WebSocket connections, Control Plane auth,
  tenant routing, PostgreSQL transactions, the committed change feed,
  visibility, Live Queries, Local Replica delivery, scheduling, storage, and
  telemetry.
- TypeScript functions execute in the bounded Rust/V8 module host.
- A module generation activates with its artifact hash. Existing calls finish
  on their original generation, while new calls use the active generation.
  Module updates do not reconnect clients.
- Reducer transaction records now include sanitized invocation provenance while
  retaining `originCommandId` for optimistic reconciliation.

## Agent function catalog

- Query, Reducer, and Action declarations accept literal `interactive`,
  `description`, tags, and confirmation metadata.
- `gonvex functions emit` writes deterministic NDJSON or TypeScript catalogs
  from the compiled artifact.
- Agent-profile Actions can call `ctx.functions.invoke` when they request the
  `functions` capability.
- The host checks the active artifact hash, portable argument schema,
  classification, tenant admission, current Member status, deadline, recursion
  depth, and normal function authorization before executing the target.
- `ctx.invocation` exposes host-owned actor and command attribution. Client
  arguments cannot change the channel or actor.

## Package migration

Upgrade these packages together to `0.5.0`:

```text
@gonvex/protocol
@gonvex/client
@gonvex/expo-sqlite
@gonvex/react
@gonvex/module-sdk
@gonvex/cli
create-gonvex
```

Generate bindings and catalogs after compiling the TypeScript module:

```bash
gonvex codegen
gonvex functions emit --format ndjson --output agent-api.ndjson
gonvex functions emit --format typescript --output agent-api.d.ts
gonvex functions check
```

This release is prepared but not published.
